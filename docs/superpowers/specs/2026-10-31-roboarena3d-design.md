# РобоАрена 3D — дизайн-документ

Дата: 2026-10-31
Статус: утверждён пользователем (объём зафиксирован, фичи больше не добавляются)

## 1. Обзор

Веб-симулятор робототехнической арены в духе TRIK RoboArena: трёхмерная арена с честной
физикой, по которой ездит виртуальный двухколёсный робот. Робот программируется настоящими
скетчами Arduino (подмножество C++), которые исполняет встроенный интерпретатор. Тот же
файл скетча без правок компилируется в Arduino IDE и работает на реальной плате.

Цели:
- 3D-визуализация с физикой (столкновения, проскальзывание колёс, толчки ящиков, рампы).
- Скетч выглядит и ведёт себя как настоящий Arduino-код (setup/loop, пины, delay, Serial, Servo).
- Три режима арены: Линия (трасса), Лабиринт, Песочница.
- Перестановка датчиков на корпусе («Сборка»): позиция датчиков линии, дальномера, бампера, серво.
- Запуск без сборки и без npm: сервер без зависимостей + start.bat.

Не-цели (v1):
- Дуэли двух роботов (сумо). Архитектура допускает второго робота позже.
- Реальная AVR-компиляция, поддержка указателей/классов/шаблонов C++.
- Мультиплеер, сохранение на сервере.

## 2. Платформа и запуск

- Чистый ES-модульный стек, без бандлера: `index.html` + `importmap` → `vendor/three.module.js`,
  `vendor/cannon-es.js`; CodeMirror 5 (UMD) как редактор кода.
- Запуск: `start.bat` → `node server.js` (порт 8123, ноль зависимостей, корректные MIME для модулей)
  → открывает `http://localhost:8123`. Альтернатива вручную: любой статический сервер.
- Библиотеки вендорятся локально (three 0.170.0, cannon-es 0.20.0, codemirror 5.65.16) —
  работает оффлайн после установки.
- Целевая среда: современный Chrome/Edge на Windows.

## 3. Структура проекта

```
roboarena3d/
├── index.html               # разметка, стили, importmap
├── server.js, start.bat     # запуск
├── vendor/                  # three.module.js, cannon-es.js, codemirror/*
└── src/
    ├── main.js              # boot, главный цикл (физика фикс. шаг + рендер), оркестрация
    ├── arduino/

    │   ├── parser.js        # AST: функции, операторы, выражения
    │   ├── interpreter.js   # асинхронный tree-walker, budget/yield
    │   └── arduinoApi.js    # pinMode/digitalWrite/... бридж к виртуальному железу
    ├── robot/
    │   ├── robot.js         # физтело, колёса (hinge-моторы), меши
    │   └── sensors.js       # HC-SR04, линия, энкодеры, бампер, серво
    ├── world/
    │   ├── scene.js         # three-сцена, свет, синхронизация физика↔графика
    │   └── arenas.js        # трасса / лабиринт / песочница + судейство
    └── ui/
        ├── editor.js        # CodeMirror, автосохранение, импорт/экспорт .ino
        ├── builder.js       # оверлей «Сборка»: перетаскивание датчиков
        └── panel.js         # сериал-монитор, панель судейства, справка, примеры
```

## 4. Интерпретатор Arduino C++

Поддерживается (подмножество, описанное в справке UI):
- Типы: `int, long, short, char, byte, bool, unsigned-варианты, float, double, void`;
  typedef-псевдонимы `uint8_t/int16_t/uint32_t/...` отображаются в канонические типы.
- `#define` (объектные), `const`, глобальные и локальные переменные, массивы (включая 2D),
  инициализаторы `{...}`.
- Операторы C с полным приоритетом: арифметика, побитовые, сравнения, логика, тернарный,
  присваивания `+=` и т.д., `++/--`.
- Управление: `if/else, for, while, do-while, switch/case/default, break, continue, return`.
- Функции пользователя с рекурсией (лимит глубины 200).
- Упрощённый `String` (конкатенация `+`/`+=`, `length()`), строковые литералы для печати.
- Arduino-библиотеки: `Servo` (attach/write/writeMicroseconds/read/detach), Serial.
- Встроенные функции Arduino: pinMode, digitalWrite, digitalRead, analogRead, analogWrite,
  delay, delayMicroseconds, millis, micros, pulseIn, attachInterrupt/detachInterrupt,
  abs/min/max/constrain/map/pow/sqrt/sin/cos/tan/atan2/floor/ceil/round/random/randomSeed,
  noInterrupts/interrupts (no-op). Константа PI, HIGH/LOW/INPUT/OUTPUT/INPUT_PULLUP и др.

Не поддерживается: указатели (кроме строковых литералов), собственные классы/структуры,
шаблоны, ссылки `&`, динамическая память, препроцессорные макросы с параметрами.
При попытке использовать — понятная ошибка с номером строки.

Исполнение:
- Асинхронный tree-walker: `delay()/delayMicroseconds()/pulseIn` ждут симулированное время;
  бюджет инструкций на кадр (антифриз): при перерасходе — уступает кадру, в Serial выдаётся
  подсказка «добавьте delay(1)» (один раз).
- `millis()/micros()` — от симулированных часов (учитывают множитель скорости и паузу).
- Целочисленная семантика: деление целых — нацело, переполнение по разрядности типа
  (int 16 бит, long 32 бита) при присваивании.
- Ошибки парсинга: строка/колонка + текст; ошибки исполнения останавливают скетч с сообщением,
  рендер не падает.

## 5. Виртуальная плата (раскладка пинов, документируется в справке)

| Устройство | Пины |
|---|---|
| Мотор левый | PWM 5 (скорость), 7/8 (направление) |
| Мотор правый | PWM 6 (скорость), 4/12 (направление) |
| Энкодеры (тики колёс) | 2 (левый), 3 (правый), через attachInterrupt CHANGE |
| Сервоприводы | 9, 10 |
| HC-SR04 | trig 11, echo 12 |
| Бампер | 13 (digitalRead; onboard LED светится при ударе) |
| Датчики линии | A0 (левый), A1 (центр), A2 (правый) |

Семантика:
- Моторы: `digitalWrite` dir-пинов задаёт полярность, `analogWrite(pwm, 0..255)` — скважность;
  угловая скорость колеса стремится к цели с инерцией, физика сама даёт проскальзывание.
- HC-SR04: честная схема trig/echo; `pulseIn(echo, HIGH[, timeout])` возвращает длительность
  эха в мкс (см = мкс/58), луч вперёд с конусом ±10°, дальность 2–400 см, нет цели → 0.
- Линия: яркость текстуры поля под датчиком → 0..1023 (чёрный ≈ 100–300, белый ≈ 900–1023).
- Энкодеры: тики от угла поворота колеса (360 тиков/оборот), вызывают обработчики
  attachInterrupt между шагами физики (с потолком вызовов за шаг).
- Бампер: короткие лучи вперёд на высоте бампера, «нажат» при препятствии ближе 12 мм.
- Серво: угол движется к цели с ограниченной скоростью (~0.1 с/60°), визуально видно.

## 6. Физика

- cannon-es, фиксированный шаг 1/120 c (2 подшага на кадр 60 Гц), решатель 10 итераций.
- Робот: корпус-бокс ≈ 180×75×240 мм, масса 0.9 кг; два ведущих колеса (Ø66 мм) на
  HingeConstraint с включённым мотором (максимум ~30 рад/с ≈ 1 м/с); опоры — две
  низкофрикционные сферы-касторы. Дифференциальный привод, поворот разностью скоростей.
- Пол: трение; стены/препятствия: реституция 0.1. Падения с рампы, толчки ящиков — честные.
- Камеры: свободная орбита (мышь) + следящая + вид сверху.

## 7. Сборка (перестановка датчиков)

- Оверлей «Сборка»: вид сверху на робота, датчики тащатся мышью по крыше;
  слайдеры: у HC-SR04 — высота (10–80 мм) и наклон вниз (0–30°); у серво — позиция;
  у датчиков линии — вынос вперёд и разлёт (перетаскивание каждого индивидуально).
- Пины фиксированы — меняется только механика крепления, влияет на показания датчиков.
- Конфиг в localStorage (`roboarena3d.mounts`), кнопка «Сбросить крепления».
- Изменения применяются сразу, в том числе во время прогона.

## 8. Арены и судейство

- **Линия (трасса)**: поле 4×3 м, белое, чёрная линия шириной 30 мм с поворотами; старт-финиш,
  чекпоинты по трассе. Судейство: таймер, проход чекпоинтов по порядку, фиксация сходов
  (центр робота дальше 60 мм от оси, дебаунс 1 с). Финиш → время + число сходов.
- **Лабиринт**: поле 4×4 м, сетка 5×5 с ячейкой 800 мм, стены 150 мм; старт в углу, выход
  отмечен. Финиш: центр робота в клетке выхода → время.
- **Песочница**: поле 4×4 м, рампа, платформа, ящики 100 мм — без судейства, свободный заезд.
- Панель судейства: таймер, прогресс, лента событий (сход, столкновение), итоговый баннер.
- Кнопки: Старт (старт таймера + скетч), Пауза, Стоп, Сброс (позиция робота, судейство, Serial).

## 9. UI

- Слева — редактор кода (CodeMirror, тема тёмная, подсветка C-подобная), статус компиляции.
- Справа — 3D-вьюпорт; оверлеи: панель судейства, баннер результата.
- Снизу — Serial-монитор (очистка, автоскролл).
- Верхняя панель: выбор арены, скорость ×0.25/×0.5/×1/×2/×4, Старт/Пауза/Стоп/Сброс,
  «Сборка», «Справка», «Примеры» (готовые скетчи на каждую арену).
- Справка: раскладка пинов, поддерживаемое подмножество C++, семантика датчиков, советы.
- Автосохранение скетча (localStorage `roboarena3d.sketch`), экспорт/импорт файла .ino.
- Интерфейс полностью на русском.

## 10. Сохранение

localStorage-ключи: `roboarena3d.sketch`, `roboarena3d.mounts`, `roboarena3d.arena`,
`roboarena3d.speed`. Сброс по кнопке в справке (очистка всех ключей).

## 11. Устойчивость

- Любая ошибка скетча/симуляции не ломает страницу: try/catch вокруг кадра, сообщение в Serial
  и статус, симуляция остаётся управляемой (Стоп/Сброс работают).
- Скетч без `loop()` или с бесконечным циклом без задержек — не вешает страницу (бюджет кадра).
- Недоступность localStorage (file:// приватный режим) — деградация без сохранения, не краш.

## 12. Приёмка (проверяется в браузере до сдачи)

1. Сервер стартует, страница открывается без ошибок в консоли.
2. Пример «Линия» проходит трассу, чекпоинты засчитываются, таймер и результат корректны.
3. Пример «Лабиринт» доезжает до выхода (на ×4 за разумное время).
4. Песочница: робот толкает ящик, заезжает на рампу.
5. Сборка: перенос датчика линии меняет показания analogRead; сброс креплений работает.
6. Ошибочный скетч → понятная ошибка с номером строки, страница жива.
7. Serial-монитор показывает вывод примеров; экспорт/импорт .ino работает.
8. Оффлайн: без интернета всё работает (библиотеки локальные).

## 13. Риски

- Интерпретатор C-подмножества — самая большая единица кода; снижается прогоном скетчей
  примеров через Node (node-repl) до браузерной интеграции.
- Тюнинг физики колёс (hinge + трение) может потребовать итераций подбора параметров.
- Разные версии three/cannon — фиксируем точные версии в vendor/.
